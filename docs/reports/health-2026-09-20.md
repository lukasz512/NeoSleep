# Health Report — 2026-09-20

## Summary
- **Critical (fix first):** `sleep_study`, `treatment_plan`, `stop_bang_screening`, `endo_intake`, and `note` queries have no territory/role scoping — any authenticated rep can list or fetch any patient's clinical data tenant-wide, unlike `patient`/`practitioner`/`organization`/`lead` which all enforce scope. This is GDPR Art. 9 special-category health data. See §1.
- **High:** CLAUDE.md is significantly out of date — it still describes session-cookie auth (`express-session`) and a `tenant_<slug>`/`tbl_`-prefixed schema, but the codebase moved to JWT access+refresh tokens (ADR-020, accepted 2026-09-16) and a `platform.*`/bare-slug-schema model months ago. Anyone (human or Claude session) reading CLAUDE.md today gets the wrong mental model of auth and schema. See §7.
- **High:** 21 of 26 API route files have zero test coverage, including PII-heavy ones (`encounter`, `note`, `sleepStudy`, `treatmentPlan`, `organization`, `practitioner`) — no 401 test, no tenant-isolation test. See §3.
- **Medium:** `patient` table has no index on `territory_id` even though territory is meant to be the primary scoping dimension — will matter once §1's fix adds `WHERE territory_id = ...` filtering to patient queries at scale. See §4.
- **Low-effort, worth doing anyway:** 1 critical + 38 high `pnpm audit` findings are all transitive dev-tooling (vite→postcss→nanoid, concurrently→shell-quote) — none reach the shipped API or frontend bundle, but a `pnpm update` would clear most of them in one pass. See §9.
