# Health Report — 2026-09-20

> Note: this repo's scheduled health-report routine fired twice today (once before PR #133 merged into `dev`, once after). This document reconciles both runs — every finding below was independently re-verified by reading the current code directly, not just carried over from either run.

## Summary
- **Critical (fix first):** `sleep_study`, `treatment_plan`, `stop_bang_screening`, `endo_intake`, and `note` queries have **no territory/role scoping at all** — confirmed directly (`grep -n "ctx.user" queries/{treatmentPlan,note,stopBangScreening,endoIntake}.ts` returns zero hits; `queries/sleepStudy.ts` never touches `ctx.user` either). Any authenticated rep can list or fetch any patient's clinical data tenant-wide, unlike `patient`/`practitioner`/`organization`/`lead`/`users` (which all call `getAllowedScopePaths`/`assertTerritoryAccessByTerritoryId`) and `encounter` (which enforces rep-ownership inline). This is GDPR Art. 9 special-category health data. See §1.
- **High:** Public contact form logs full PII (name, phone, email, city, message) to plaintext console output with no retention/access control (`apps/api/src/routes/website-contact.ts:12`) — quick fix, real GDPR exposure. See §1.
- **High (functional bug):** `PresentationViewer.vue`'s `&--rotated` SCSS rule has no `lang="scss"` on its `<style>` block, so it's parsed as plain CSS nesting (matches the build's own warning) — the tablet landscape-rotation transform for HCP presentations likely never applies. This is the rep app's core in-visit feature. See §2.
- **High:** CLAUDE.md is significantly out of date on three fronts — it still describes session-cookie auth (`express-session`, confirmed no longer even a dependency) instead of the JWT access+refresh model actually in place (ADR-020), documents a `tenant_<slug>`/`tbl_*`-prefixed schema instead of the real `platform.*` + bare-company-slug model, and lists a composable (`useAppConfig.ts`) that doesn't exist anywhere in the repo. See §7.
- **High:** 11 of 23 real API route files (`lookup`, `push`, `invite`, `notification`, `organization`, `partners/orthoapnea-resources`, `partners/orthoapnea-status`, `users`, `sleepStudy`, `treatmentPlan`, `note`) have no route-level (401/auth-boundary) test — verified against `server.spec.ts`'s broad but shallow coverage plus each route's own spec file. See §3.
